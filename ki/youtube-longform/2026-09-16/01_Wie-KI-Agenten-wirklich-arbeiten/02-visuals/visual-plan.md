# Visual Plan

Alle Kapitel sind `REMOTION_NATIVE`. Keine externen Bilder geplant.

| Kapitel | Hauptvisual | Zustandsentwicklung |
|---|---|---|
| Hook | Chatbot-Blase → Agent-Workspace | einzelne Antwort zerlegt sich in Ziel, Tools, Aktionen und Feedback |
| Chatbot vs. Agent | Split-Screen | links Frage→Antwort; rechts Ziel→mehrstufige Arbeitskette |
| Vier Bausteine | Agent-Kern mit vier Modulen | Modell, Regeln, Tools und Kontext rasten nacheinander ein |
| Agenten-Loop | großer kreisförmiger Loop | Ziel → Beobachten → Entscheiden → Handeln → Feedback → nächste Runde |
| Beispiel | Dokument-Desk | Dateien öffnen → Punkte extrahieren → Konflikt erkennen → nachschlagen → Entwurf → Prüfung |
| Werkzeuge | dynamische Toolbox | Suche, Dateien, Code und Browser werden je nach Aufgabe selektiv aktiviert |
| Risiken | Fehler-Kaskade + Fremdinstruktion | falsche Annahme wandert durch mehrere Schritte; externe Anweisung wird als Risiko isoliert |
| Kontrolle | Permission-Gates | Tool-Rechte, Bestätigung, Verifikation und Stop-Kriterium schließen den Loop ab |
| Einsatz & Schluss | Workflow vs. Agent + Gesamtmodell | fester Pfad gegen adaptiven Pfad; finale Agenten-Anatomie bleibt als mentales Modell stehen |

## Stil

- heller editorialer Hintergrund
- dunkle Typografie
- Marken-Lila für aktive Zustände
- Grün nur für bestätigte/erfolgreiche Zustände
- Rot nur für Fehler/Risiko
- pseudo-3D über Layering, Schatten, Perspektive und große Objekte
- keine generische Neon-/Cyberpunk-Optik
- keine Screenshot-Collagen
- kein Transcript als Design-Ersatz
