# Visual Story Plan — GPT-6 Astra: Agenten & Kontrolle

## Leitidee

`OPEN_ENDED_STORY_DRIVEN`. Das Video ist kein Slide-Deck. Jede Sprecheridee bekommt einen visuellen Mechanismus. Echte Quellen beweisen reale Aussagen; native Remotion-/Skia-/Three-Visuals erklären Zusammenhänge. Reale B-Roll schafft Rhythmuswechsel, dient aber niemals als Fake-Beleg für Astra.

## Look

- 16:9, 1920×1080, 30 FPS
- heller editorialer Premium-Look
- Hintergrund überwiegend warmes Off-White / sehr helles Grau
- Primär: `#1A1A2E`
- Akzent: `#B98CFF`
- Tiefenakzent: `#6E45C9`
- Grün ausschließlich positiv/freigegeben
- Rot ausschließlich Risiko/Fehler/Block
- keine Cyberpunk-Neon-Welt, keine Roboterköpfe, keine generischen KI-Gehirne
- große, TV-lesbare Typografie

## Visual World A — Source Desk

**Funktion:** Beweis.

- echte OpenAI-Seiten als lokale Screenshots
- relevante Passage wird mit Mask/Spotlight/Underline isoliert
- Source-Domain und Datum klein sichtbar
- Screenshot nie als Vollbild stehen lassen: Crop → Highlight → Kontextkarte → wieder raus
- leichte räumliche Tiefe statt Browser-Chrome

## Visual World B — Agent Workspace

**Funktion:** erklären, was „mehrstufige Arbeit“ bedeutet.

- ein Ziel-Block startet links
- daraus verzweigt eine Task-Kette: Search → Browser → File → Code → Tool → Review → Result
- Desktop-/Browserflächen als abstrahierte native UI, ausdrücklich keine Fake-OpenAI-Produktoberfläche
- einzelne Tool-Karten reagieren auf gesprochenen Inhalt
- Kamera bewegt sich entlang des Workflows

## Visual World C — Benchmark Lab

**Funktion:** Zahlen zeigen und sofort relativieren.

- 98 / 99.9 / 100 als drei große Messkörper
- darunter klar: `OpenAI claim`
- Messkörper verwandeln sich in drei enge Testfenster
- eine größere, unordentliche Realweltfläche erscheint außerhalb dieser Fenster
- Kernaussage visuell: `Benchmark ≠ komplette Realität`

## Visual World D — Access & Cyber Architecture

**Funktion:** Critical Cyber ohne operative Hacking-Anleitung erklären.

- Modellkern in der Mitte
- außen: Network / Terminal / Files / Accounts / Tools
- Access-Gates öffnen sich nur, wenn Berechtigung erteilt wird
- `CRITICAL` erscheint als Stufe innerhalb eines ausdrücklich mit `OpenAI Preparedness Framework` beschrifteten Messsystems
- unbekannte Schwachstelle nur als abstrakter Knoten / gebrochene Vertrauenslinie visualisieren
- keine echten Exploit-Schritte, Payloads, Commands oder Zielsysteme
- kurze reale Infrastruktur-B-Roll als visuelle Atempause

## Visual World E — Monitorability Room

**Funktion:** Alignment und Monitorability auseinanderziehen.

- zwei unabhängige Achsen: `Alignment` und `Monitorability`
- Alignment bewegt sich nach oben, Monitorability nach unten
- eine Agenten-Trajektorie läuft durch einen Monitor
- CoT-Spur wird kürzer und informationsärmer, Aktionen bleiben sichtbar
- Sandbagging: tatsächliche Capability-Linie bleibt hoch, sichtbare Eval-Leistung fällt absichtlich ab
- Label immer `adversarial evaluation`
- Gegenbalance anschließend sichtbar: `overall boundary adherence improved`
- Steganography-Abschnitt endet mit `no evidence found`

## Visual World F — Work / Agent Infrastructure

**Funktion:** aktuellen Produktkontext erklären.

- echte Business-/Agents-API-Screenshots als Proof
- danach native Systemansicht: Session → Tools → Files → Sandbox → Subagents
- klarer Trenner: `Agents API = infrastructure`, `Astra = model`
- keine Verschmelzung zu einer erfundenen Produktoberfläche

## Visual World G — Control Stack / Payoff

**Funktion:** praktische Schlussfolgerung.

- Modell zunächst allein in der Mitte
- darum baut sich schrittweise ein Kontrollsystem auf:
  1. least privilege
  2. sandbox
  3. audit log
  4. spend/action limits
  5. approval gate
  6. independent monitor
  7. human review
- riskante Aktion läuft gegen `APPROVAL REQUIRED`
- erst nach Freigabe wird der Pfad grün
- Schlussbild: Modell klein im Zentrum, Architektur groß darum herum

# Kapitelregie

## Kapitel 1 — Der echte Sprung

- 0–erste Voice-Beats: schneller Source-Montage-Start mit echter Astra-Launch-Seite
- `GPT-6 ASTRA` löst sich aus dem Screenshot als typografisches Objekt
- Benchmark-Zahlen blitzen kurz auf und werden zur Seite geschoben
- stattdessen wächst eine Task-Kette über den Bildschirm
- Cut auf Agents-API-Source als aktueller Kontext
- Ende: `VON ANTWORTEN → ZU ARBEITSABLÄUFEN`

## Kapitel 2 — Arbeitsagent

- Agent Workspace fährt entlang eines konkreten abstrakten Jobs
- Ziel → Recherche → Webseite → Datei → Code → Ergebnis
- an einer Stelle 3–5 s echte Coding-B-Roll
- B-Roll bekommt keinen Astra-Claim; Label optional `generic coding footage`
- Rückkehr in native Workflow-Welt

## Kapitel 3 — Benchmarks

- drei Zahlen groß und klar
- jede Zahl mit kleinem `OpenAI reported`
- anschließend Messfenster-Metapher
- Kamera zoomt heraus: außerhalb der drei Tests liegt die komplexe Realwelt
- kein Score-Spam, keine zusätzlichen Demo-Zahlen

## Kapitel 4 — Critical Cyber

- echte Safety-Source
- Preparedness-Leiter bis Critical
- Modellkern + Tool-/Access-Ring
- USB-Clip maximal ~2 s als Access-Metapher
- Schutzmaßnahmen bauen sich wie physische Schichten auf
- Server-/Infrastruktur-Still oder lizenzierte B-Roll als kurzer Rhythmuswechsel

## Kapitel 5 — Monitorability

- zwei Achsen Alignment/Monitorability
- System-Card-Proof
- CoT-Spur wird kürzer, Monitor verliert Signal
- Sandbagging-Visual: Capability bleibt, gemessener Output sinkt
- roter `adversarial`-Rahmen verhindert Überdramatisierung
- anschließend Counterweight: bessere Boundary-Adherence
- Ende: `ALIGNMENT ≠ MONITORABILITY`

## Kapitel 6 — Work & Agents API

- echte Business-Seite → echte Agents-API-Seite
- native Diagrammwelt zeigt Harness, Sessions, Tools, Sandbox, Subagents
- Plan-/Rollout-Hinweis aus Help Center nur kurz und aktuell
- wichtige Trennung visuell: Modell vs. Infrastruktur

## Kapitel 7 — Kontrolle

- Chatbot-Fehler = falscher Text
- Agenten-Fehler = Aktion wandert durch Tool-Pfad
- Action stoppt an Approval Gate
- kompletter Control Stack baut sich auf
- letzte Frage groß: `WIE VIEL KONTROLLE BEHALTEN WIR?`
- End-Hold 1–1.5 s nach Voice-Ende, keine lange Stille

# Motion-Regeln

- Bedeutung entscheidet über Bewegung, nicht ein fixer Timer
- Cold Open sichtbar dichter als Proof-Passagen
- Source-Proofs dürfen ruhig sein, aber nie als 15-s-Standbild
- kein Zustand >= 15 s praktisch unverändert
- ab ~8 s statischer Wirkung bewusst Reframe/Detail/Highlight oder realer Hold-Review
- keine Zooms/Whooshes ohne Storyfunktion
- große Bewegungen für Kapitelwechsel; Micro-Motion für laufende Erklärung
- Three.js nur dort, wo räumliche Access-/Systemarchitektur wirklich verständlicher wird
- Skia für Monitor-Linien, Masken, Pfade und dynamische Diagrammzustände
- Recharts nur für echte strukturierte Vergleichsdaten, nicht als Dekoration

# SFX-Konzept nach Voice-Lock

- source reveal: kurzer paper/digital settle
- workflow node activation: leiser tick/click
- benchmark lock: drei unterschiedliche soft impacts
- Critical threshold: tiefer kontrollierter hit
- permission gate: lock/click
- monitor scan: subtiler sweep
- sandbagging drop: kurzer low drop
- approval stop: muted stop impact
- final control stack: mehrere sehr leise locks, letzter gemeinsamer settle

Voice bleibt dominant. Kein permanenter Whoosh-Teppich.

# Nicht erlaubt

- Fake-Astra-Webseite
- generiertes Produkt-UI als Proof
- Placeholder wie `Astra praktisch Visual`
- zufällige Stock-B-Roll ohne semantischen Zusammenhang
- militärische/unpassende Scout-Treffer nur weil Query-Tokens zufällig matchen
- operative Cyberanleitungen
- feste gleich lange Kapitel
