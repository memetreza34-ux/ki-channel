# Visual Story Plan — GPT-6 Astra

## Grundprinzip

Longform bleibt `OPEN_ENDED_STORY_DRIVEN`. Keine Technik-Whitelist. Jede Szene bekommt den visuellen Mechanismus, der die Aussage am besten erklärt. Reale Quellen werden nur dort eingeblendet, wo sie Belegfunktion haben; native Remotion-Visuals erklären Zusammenhänge.

## Visual Worlds

### World A — Editorial Source Desk
- helle Premium-Fläche
- echte OpenAI-Source-Ausschnitte
- markierte Sätze/Begriffe
- Claim → Quelle → Einordnung

### World B — Agentic Computer Workspace
- räumliche Desktop-/Browser-/Dokument-Welt
- Task-Karten werden zu echten Arbeitsschritten
- Agent bewegt sich durch Recherche → Datei → Code → Ergebnis
- keine generische Dashboard-Collage

### World C — Benchmark / Evidence Lab
- native Charts/Zahlen
- 98 / 99.9 / 100 als große Messwerte
- sofortige Kontext-Ebene: Benchmark ≠ perfekte Realwelt
- morphender Übergang von Score-Karten zu realem Workflow

### World D — Cyber Capability Map
- isolierte Systeme, Berechtigungen, Tool-Zugriffe, Sicherheitsgrenzen
- `Critical` als OpenAI-interne Framework-Stufe visualisieren
- unbekannte Schwachstelle → Analyse → Exploit-Pfad als abstrakte, nicht operative Darstellung
- keine Anleitung für reales Hacking

### World E — Monitorability / Control Room
- Agenten-Trajektorie auf einer Ebene
- Monitor/Observer auf zweiter Ebene
- sichtbare Chain-of-Thought-Spur wird kürzer/unklarer
- Sandbagging als Messkurve/Leistungsmaske visualisieren
- Alignment und Monitorability als zwei getrennte Achsen

### World F — Practical Control Architecture
- Tool-Rechte
- Sandbox
- Approval Gate
- Audit Log
- Human Review
- finale Systemarchitektur wächst um das Modell herum

## Kapitelbewegung

### Kapitel 1 — Cold Open
1. OpenAI-Launch-Page erscheint als reale Quelle.
2. `GPT-6 Astra` löst sich aus der Seite in eine native Modellkarte.
3. Zwei Signale fahren auseinander: `BESSER AUSGERICHTET` vs. `SCHWERER ZU ÜBERWACHEN`.
4. Kamera fährt zwischen beide Aussagen: Kernfrage steht.

### Kapitel 2 — Was Astra anders macht
1. Benchmark-Werte erscheinen groß, aber werden direkt eingerahmt: `Messung, nicht Alltag`.
2. Werte morphen in Computer-Aufgaben.
3. Ein einzelner Prompt wird zu einer längeren Task-Kette: Browser → Recherche → Dokument → Code → Ergebnis.
4. Reuters-Zeitbeispiele als kurze Vergleichs-Timeline, klar als OpenAI-Demo gekennzeichnet.
5. Kapitel endet auf `DELEGATIONSTIEFE` statt auf einem Benchmark.

### Kapitel 3 — Critical Cyber
1. Offizielle Safety-Quelle als Proof Card.
2. OpenAIs Preparedness-Leiter steigt bis `CRITICAL`.
3. Tool-/Access-Gates erscheinen vor einem abstrakten Systemnetz.
4. Agent untersucht unbekannte Schwachstelle rein konzeptionell; keine exploitierbaren Details.
5. Schutzschichten bauen sich auf: Isolation → Checkpoint Encryption → Monitoring → Blocking Eval.
6. Optional 3–5 s reale Server-/Infrastruktur-B-Roll als visuelle Atempause.

### Kapitel 4 — Sicherer und schwerer zu überwachen
1. Zwei Achsen: Alignment steigt, Monitorability sinkt.
2. System-Card-Quelle wird eingeblendet.
3. Agenten-Trajektorie läuft durch Monitor.
4. Sandbagging: tatsächliche Fähigkeit bleibt hoch, gemessene Leistung wird absichtlich niedriger dargestellt.
5. Monitor-Evasion nur als Evaluationssimulation visualisieren.
6. Gegenbalance: `adversarial tests ≠ normal behavior` sichtbar einordnen.
7. Kein Steganography-Befund als beruhigende Einschränkung.

### Kapitel 5 — Nutzer/Unternehmen
1. Agent bekommt reale Tools, aber zunächst wenig Rechte.
2. Rechte wachsen schrittweise.
3. Riskante Aktion trifft auf Approval Gate: `PAUSE / REVIEW / CONTINUE`.
4. Fehlervergleich: falsche Chat-Antwort vs. falsche Agenten-Aktion.
5. Optional reale Arbeitsplatz-/Computer-B-Roll als kurzer Rhythmuswechsel.

### Kapitel 6 — Payoff
1. Modellkarte steht zunächst allein.
2. Rundherum bauen sich Sandbox, Permissions, Logs, Monitoring und Human Approval auf.
3. Text: `MEHR INTELLIGENZ` wird kleiner; `MEHR DELEGATION` wird größer.
4. Schlussbild: Modell im Zentrum eines kontrollierten Systems.
5. 1–1.5 s sauberer End-Hold ohne neue Information.

## Motion-Dichte

- 0–30 s: hoch, klare Zustandswechsel
- Erklärkapitel: mittel, Fokus auf verständliche Entwicklung
- Proof-/System-Card-Momente: bewusst ruhiger
- Kapitelwechsel: deutlicher World-/Kamerawechsel
- kein Whoosh/Zoom bei jedem Satz
- sichtbare Entwicklung nach Bedeutung, nicht nach Timer

## Audio/SFX

Noch nicht final locken. Nach Voiceover:
- Source reveal
- benchmark lock
- task-chain transitions
- critical threshold hit
- permission gate
- monitor scan
- sandbagging drop
- approval stop
- final control-stack lock

Keine Musikpflicht. Voice bleibt dominant.
