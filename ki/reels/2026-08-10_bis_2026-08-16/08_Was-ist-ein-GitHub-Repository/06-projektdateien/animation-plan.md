# Animation Plan — 16 Visual Beats

1. `GitHub-Projekt öffnen` → Projektordner steht ab Frame 0 sichtbar im Zentrum → Deckel öffnet sich → `NEW_BUILD`.
2. `Repository` → mehrere klare Projektdateien fahren aus dem Ordner → vollständiger Arbeitsordner sichtbar → `NEW_BUILD`.
3. `mit Gedächtnis` → hinter dem Ordner entsteht eine Commit-Zeitleiste → Ordner bekommt sichtbare Geschichte → `NEW_BUILD`.
4. `Code, Bilder, Dokumentation, Konfiguration` → vier große Dateitypen ordnen sich nacheinander → Inhalt wird konkret → `NEW_BUILD`.
5. `welche Datei geändert wurde` → eine Dateikarte leuchtet und zeigt Delta → Änderung wird lokalisiert → `NEW_BUILD`.
6. `wann / wer` → Zeit- und Personen-Metadaten docken an die Änderung → Veränderung bekommt Kontext → `NEW_BUILD`.
7. `Zwischenstand heißt Commit` → aktueller Dateizustand wird als Snapshot in einen Commit-Knoten eingerastet → `NEW_BUILD`.
8. `viele Commits` → weitere Commit-Knoten bauen eine Geschichte auf → `NEW_BUILD`.
9. `was wurde geändert` → Diff-Karte zeigt vorher/nachher → `NEW_BUILD`.
10. `wo funktionierte Code noch` → Timeline-Cursor fährt zu älterem grünen Zustand zurück → `NEW_BUILD`.
11. `Branches getrennt ausprobieren` → Hauptlinie teilt sich sichtbar in Feature-Branch → `NEW_BUILD`.
12. `stabile Version nicht anfassen` → Main bleibt ruhig/gesperrt, Feature bewegt sich separat → `NEW_BUILD`.
13. `Pull Request geprüft` → Feature läuft durch große Review-Gate-Karte → `NEW_BUILD`.
14. `zusammengeführt` → Branch verschmilzt wieder mit Main, Merge-Knoten wird grün → `NEW_BUILD`.
15. `Dateien + Verlauf + Zusammenarbeit` → drei große Module verbinden sich zu einem zentralen Repo → `NEW_BUILD`.
16. `komplette Entwicklung des Projekts` → Repo wandert zu zweitem Nutzer und zeigt weiterhin Dateien + Timeline + Branch-Historie → `NEW_BUILD`.

Timing wird in Phase 3 gegen das echte Voiceover neu kalibriert. Kein bedeutungstragender Wechsel darf mehrere Sekunden visuell statisch bleiben.
