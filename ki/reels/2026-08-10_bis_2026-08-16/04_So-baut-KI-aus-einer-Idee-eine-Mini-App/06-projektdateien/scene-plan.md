# Scene Plan

## Szene 1 — Von Idee zu Prototyp
**Kernaussage:** KI kann schnell einen Entwurf erzeugen, aber ein vager Einzeiler ist kein belastbarer Auftrag.
**Visual:** große Idee-Karte → sichtbare App-Vorschau; danach vager Prompt kippt in „zu offen“.

## Szene 2 — Erst Struktur, dann Code
**Kernaussage:** Ziel, Funktionen und Ablauf werden zu einer verständlichen App-Struktur.
**Visual:** großer Plan mit Ziel, UI, Eingaben, Logik und Ergebnis; Kacheln bauen sich semantisch auf.

## Szene 3 — Code wird zusammengesetzt
**Kernaussage:** ein Prototyp entsteht aus zusammenarbeitenden Bausteinen statt aus einem mystischen Codeblock.
**Visual:** Monolith teilt sich in UI, Daten und Logik; Module verbinden sich mit großer App-Vorschau.

## Szene 4 — Der erste Entwurf scheitert
**Kernaussage:** Testen macht konkrete Fehler sichtbar.
**Visual:** Button-, Daten- und Mobile-Fehler werden nacheinander rot erkannt und jeweils sichtbar korrigiert.

## Szene 5 — Testen macht ihn brauchbar
**Kernaussage:** KI schlägt vor; Mensch entscheidet; der iterative Workflow macht den Prototyp belastbarer.
**Visual:** Diagnose → Patch → Freigabe-Gate → Idee/Struktur/Code/Test/Fix → finaler Prototyp.

Alle Szenen: große Kernvisuals, minimale interne Labels, keine Animation in/unter der Caption-Zone.
